# Contributing

Thanks for your interest in `renovate-mcp`. Before opening a non-trivial PR, please skim [`CLAUDE.md`](./CLAUDE.md) — it documents the architectural invariants this repo cares about (when to shell out to the Renovate CLI vs. stay in-process, the `write_config` validate-then-rename flow, how the preset catalogue is generated, what `preview_custom_manager` deliberately does *not* implement, and so on). Most review feedback lands on those invariants, so reading them first will save a round trip. The v1 roadmap is complete; see [`docs/roadmap.md`](docs/roadmap.md) for carry-over and backlog candidates if you're looking for something to work on, or check the [open GitHub issues](https://github.com/tibuntu/renovate-mcp/issues) for anything already in flight.

A few conventions worth knowing up front: commits use [Conventional Commits](https://www.conventionalcommits.org/) (release-please drives versioning and `CHANGELOG.md` from the prefixes — see [Release flow](./docs/development.md#release-flow)). Run `npm run typecheck` and `npm test` before pushing; CI runs both on the Node version pinned in `.nvmrc` and will reject anything that doesn't pass. For security issues, please follow [`SECURITY.md`](./SECURITY.md) rather than opening a public issue.
